## An Array-Based Stack

A stack adds and removes at one end only, so everything happens at the **top**.
In an array that end is just an index: `top` holds the position of the most
recent element, and `-1` means the stack is empty.

Three methods of `ArrayStack<T>` are left blank. Fill them in.

| Method | What it must do |
|---|---|
| `void push(T newEntry)` | Put `newEntry` on the top. |
| `T pop()` | Remove and return the top element. |
| `T peek()` | Return the top element without removing it. |

Everything else is provided: the `StackInterface<T>` declaration, the
constructors, `isEmpty`, `size`, `clear`, the private helpers
`checkIntegrity` and `ensureCapacity`, and all input and output handling.

### An empty stack

`pop` and `peek` have nothing to return when the stack is empty. This is called
**underflow**, and this implementation reports it by throwing a
`RuntimeException`; the driver catches that and prints `empty`.

Reading outside the array is a different thing, and the driver prints `crash`
for it instead. A correct solution never produces that line.

### Capacity

The stack starts with room for 50 elements and `ensureCapacity` doubles the
array when it fills. Call it before you store, or the 51st element has nowhere
to go.
