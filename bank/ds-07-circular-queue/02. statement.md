## A Circular Array-Based Queue

A queue takes from one end and adds at the other. Done naively in an array,
removing from the front means pulling everything else forward, which is
$O(n)$. Moving a `front` index instead avoids the shifting but strands the
slots behind it: the array fills up while empty space sits at the beginning.

A **circular queue** joins the two ends of the array into a ring, so those
slots come back around and get reused. The modulo operator is what makes the
ring.

Three methods of `CircularQueue<T>` are left blank. Fill them in.

| Method | What it must do |
|---|---|
| `void enqueue(T newEntry)` | Add `newEntry` at the rear. |
| `T dequeue()` | Remove and return the front element. |
| `T getFront()` | Return the front element without removing it. |

Everything else is provided: the `QueueInterface<T>` declaration, the
constructor, `isEmpty`, `isFull`, `size`, `clear`, and all input and output
handling. The fields are `data`, `capacity`, `front` (the index of the first
element) and `count` (how many elements are stored).

### The boundaries are not symmetric

- `enqueue` on a **full** queue throws a `RuntimeException`; the driver
  catches it and prints `full`.
- `dequeue` and `getFront` on an **empty** queue return `null`; the driver
  prints `empty`.

Section 6.1 gave both ways of reporting that an operation has nothing to work
with, and this class uses one of each.

Reading outside the array is neither of those, and the driver prints `crash`
for it. A correct solution never produces that line.
