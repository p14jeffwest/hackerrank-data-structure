## Building a Linked List

The array-based list had to shove elements aside to make room. A linked list
does not: each node holds a reference to the next one, so inserting means
re-pointing two references and nothing else moves.

The cost lands somewhere else instead. There is no index to jump to, so
reaching position `i` means walking `i` links from `head`.

Three methods of `LinkedList<T>` are left blank. Fill them in.

| Method | What it must do |
|---|---|
| `add(int givenPosition, T newEntry)` | Insert `newEntry` at that position. |
| `T remove(int givenPosition)` | Remove the node at that position and return its data. |
| `int indexOf(T anEntry)` | Return the position of `anEntry`, or `-1` if it is not in the list. |

Everything else is provided: the `ListInterface<T>` declaration, `add` at the
end, `get`, `size`, `toString`, the private helpers `addFirst`, `addLast`,
`removeFirst` and `getNodeAt`, and all input and output handling.

### Positions

Positions start at **0**. The two bounds are not the same:

- `add(int, T)` accepts `0 <= i <= size()`. Inserting **at** `size()` appends.
- `remove(int)` and `get(int)` accept `0 <= i < size()`.

Anything outside those ranges prints `error`.

> Note the difference from the array-based version, where inserting at
> `size()` was an error. Both are the same ADT; the two implementations simply
> draw the line in different places.

### The list keeps two references

`head` points at the first node and `tail` at the last, which is what lets
`addLast` finish without walking the list. Both have to stay correct after
every change you make.
