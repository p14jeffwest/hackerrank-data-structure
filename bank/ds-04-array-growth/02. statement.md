## What the List Costs

An array-based list charges for two things you never asked for. Inserting in
the middle **shifts** the elements behind it. Running out of room **copies**
everything into a bigger array.

Given a starting capacity and a sequence of operations, report the total.

| Operation | Elements moved | Grows first? |
|---|---|---|
| `add` | 0 | yes, if full |
| `addAt i` | `size - i` | yes, if full |
| `removeAt i` | `size - 1 - i` | never |

Growing means copying every element currently stored into an array of
**double** the capacity. It happens *before* the operation does its own work,
and only when the list is completely full. Removing elements never shrinks the
capacity.

Print three numbers per test case: total elements moved by shifting, total
elements copied by growing, and the final capacity.

### Worked example

Starting capacity 2, six operations:

| # | Operation | Moved | Copied | Size after | Capacity after |
|---|---|---|---|---|---|
| 1 | `add` | 0 | 0 | 1 | 2 |
| 2 | `add` | 0 | 0 | 2 | 2 |
| 3 | `add` | 0 | 2 | 3 | 4 |
| 4 | `addAt 0` | 3 | 0 | 4 | 4 |
| 5 | `removeAt 1` | 2 | 0 | 3 | 4 |
| 6 | `add` | 0 | 0 | 4 | 4 |

Totals: **5 moved, 2 copied, capacity 4**.

Operation 3 found the list full at size 2, so it copied both elements into an
array of capacity 4 and then stored. Operation 4 pushed all 3 elements back one
slot. Operation 5 pulled the 2 elements behind position 1 forward.
